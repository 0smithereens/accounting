# 会计自动化记账系统

[![CI](https://github.com/your-org/accounting-automation/actions/workflows/ci.yml/badge.svg)](https://github.com/your-org/accounting-automation/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Node.js](https://img.shields.io/badge/node-%3E%3D22.18-brightgreen.svg)](https://nodejs.org/)
[![Tests](https://img.shields.io/badge/tests-90%20passed-brightgreen.svg)](#测试)

识别 Excel / Word 单据，按可配置规则生成标准借贷会计分录，导出可直接导入财务软件的记账凭证。

面向**会计日常办公自动化**：把银行流水、发票台账、报销单、工资表、合同这些原始文件丢进来，
系统自动完成「识别字段 → 判断业务性质 → 匹配会计科目 → 生成凭证 → 校验借贷平衡」的全过程。

**数据不出本机** —— 零网络请求、无遥测、不调用任何云端 API。

## 能做什么

| 输入 | 识别内容 | 产出 |
| --- | --- | --- |
| 银行流水 / 对账单（Excel、CSV） | 日期、摘要、对方户名、收付方向、金额、余额勾稽 | 收款、付款、手续费、利息、税款、社保、工资、理财、内部划转等分录 |
| 发票台账（Excel） | 发票号、购销方、货物名称、金额、税率、税额 | 进项/销项判断，价税分离，专票抵扣 / 普票全额入账 |
| 报销单 / 费用明细（Excel） | 报销人、部门、费用类别、金额、税额 | 按费用类别与部门归集到销售费用 / 管理费用明细科目 |
| 工资表（Excel） | 姓名、部门、应发、社保、公积金、个税、实发 | 计提、发放、单位承担社保三组凭证，自动校验工资勾稽 |
| Word 合同（.docx） | 合同编号、甲乙方、大小写金额、税率、结算方式、付款节点 | 合同台账；仅在合同写明「已收付」时才生成分录 |

关键能力：

- **金额零误差**：全程以「分」为单位的整数运算，不使用浮点数。价税分离保证 `不含税 + 税额 = 价税合计`。
- **借贷恒平衡**：每张凭证都校验 `Σ借方 = Σ贷方`；万一规则配错，差额会挂到待处理科目并报错，绝不悄悄丢钱。
- **全链路可溯源**：每条分录都能追到「哪个文件、哪个工作表、哪一行、命中哪条规则」。
- **跨单据去重**：自动识别「银行代发工资」与「工资表发放」这类同一笔业务出现在两份文件里的情况，避免重复记账。
- **大小写金额交叉校验**：合同大小写金额不一致时以大写为准并告警。
- **规则全可配**：科目表、记账规则、去重规则都是 YAML，改配置不用改代码。

## 快速开始

环境要求：**Node.js ≥ 22.18**（用到原生 TypeScript 支持，无需编译步骤）。

```bash
# 1. 安装依赖
npm install

# 2. 校验配置（会检查科目表、规则引用的科目是否存在等）
npm run check

# 3. 生成样例单据并试跑一遍
npm run samples
node src/cli.ts samples --period 2024-01

# 4. 处理你自己的文件
node src/cli.ts 银行流水.xlsx 发票台账.xlsx 工资表.xlsx --period 2024-01
```

生成的凭证在 `out/` 目录下。

> **重要**：第一次使用前请修改 `config/settings.yaml` 里的 `companyNames`，
> 填成你公司的工商全称。发票判断进项/销项、合同判断甲乙方都依赖它。

## 支持的单据类型

系统会自动判断每个文件属于哪一类（依据表头结构打分），也可以用 `--kind` 手动指定。

### 银行流水 / 对账单

三种常见记法都支持：

- **借贷两列**：`借方发生额` / `贷方发生额`
- **金额 + 方向列**：`交易金额` + `借贷标志`（借/贷、收/付、进/出、+/-、D/C 都能识别）
- **单列带符号**：金额为负表示支出

另外还会：

- 跳过标题行、空行、`合计` 行
- 用「余额」列做勾稽校验（上一行余额 ± 本行金额 = 本行余额），不符时告警
- 识别本企业账户之间的内部划转
- 支持 `.csv`（自动识别 UTF-8 / GBK 编码）

### 发票台账

- 通过购方/销方名称与 `companyNames` 比对，判断是**进项**还是**销项**
- 按发票种类判断**是否可抵扣**：专用发票（含数电专票）拆出进项税额；普通发票、免税发票全额计入成本费用
- 台账只给「价税合计 + 税率」时自动做价税分离
- 台账给了不含税金额与税额时，会校验 `不含税 + 税额 = 价税合计`，不符则以价税合计为准重算并告警
- 未给税率时按货物/服务名称推断（13% / 9% / 6% / 3%）

### 报销单 / 费用明细

- 费用类别会规范化：「差旅/出差/机票/住宿」→ `差旅费`，「招待/餐费/宴请」→ `业务招待费`，以此类推
- 同一日期 + 同一报销人 + 同一类别 + 同一部门的多行明细会自动合并为一张报销单
- 销售部/市场部的费用自动记入 `销售费用`，其余记入 `管理费用`
- 有可抵扣税额时拆出进项税额；没有时全额入账（同一个规则同时适配两种情况）

### 工资表

一个工资表会产出**三类**单据：

1. **计提**（每人一条）：`借 管理费用/销售费用/制造费用-工资`，`贷 应付职工薪酬-工资`
2. **发放**（全表汇总一条）：`借 应付职工薪酬-工资`，`贷 银行存款` + `应交个人所得税` + `其他应付款-社保/公积金个人部分`
3. **单位承担社保公积金**（按部门汇总）：`借 费用-社保公积金`，`贷 应付职工薪酬-社保/公积金`

会校验会计恒等式：**应发 = 实发 + 个税 + 个人社保 + 个人公积金 + 其他扣款**，不符时逐人告警。

### Word 合同

抽取：合同编号、名称、甲乙方、小写金额、大写金额、税率、结算方式、付款节点（预付款/进度款/尾款/质保金比例）、履约期限。

**合同本身不是会计事项**，默认只登记台账、不生成凭证。只有当合同正文明确写了「已收款」「已付款」「款项已结清」这类已发生事实时，才会按下述规则生成分录。

## 命令行用法

```bash
# 处理多个文件（自动识别类型）
node src/cli.ts 流水.xlsx 发票.xlsx --out out/2024-01凭证.xlsx

# 处理整个目录（-r 递归子目录）
node src/cli.ts ./单据 -r --period 2024-01

# 手动指定单据类型（自动识别失败时）
node src/cli.ts --kind bank 某银行流水.csv

# 工资表没有月份列时，用 --period 指定会计期间
node src/cli.ts --kind payroll --period 2024-01 工资表.xlsx

# 关闭跨单据去重（默认开启）
node src/cli.ts samples --no-dedup

# 关闭自动配平（借贷不平时只告警，不挂待处理科目）
node src/cli.ts samples --no-balance
```

辅助命令：

```bash
node src/cli.ts check            # 校验配置：科目表、规则引用的科目、企业名称
node src/cli.ts rules            # 列出全部记账规则（按优先级）
node src/cli.ts explain 流水.xlsx # 诊断识别过程：表头打分、提取结果、规则匹配明细
```

`explain` 在识别不准时特别有用，它会告诉你每个字段是怎么被识别的、为什么某条规则没匹配上。

**老式 `.xls` 文件**（ExcelJS 读不了二进制格式）需要先转换：

```powershell
powershell -ExecutionPolicy Bypass -File tools/convert-xls.ps1 -Path .\银行流水.xls
```

## 配置说明

所有配置在 `config/` 目录，改完刷新页面或重新运行命令即可生效。

```
config/
├── chart-of-accounts.yaml   会计科目表（143 个常用科目）
├── settings.yaml            全局设置：企业名称、凭证字、兜底科目、报销贷方科目…
├── dedup.yaml               跨单据重复业务检测规则
└── mappings/
    ├── bank.yaml            银行流水规则
    ├── invoice.yaml         发票规则
    ├── expense.yaml         报销单规则
    ├── payroll.yaml         工资规则
    └── contract.yaml        合同规则
```

### 科目表 `chart-of-accounts.yaml`

```yaml
- { code: "6602.05", name: 水电费, category: profit, parent: "6602", auxiliary: [department] }
```

- `category`：`asset` 资产 / `liability` 负债 / `equity` 所有者权益 / `cost` 成本 / `profit` 损益
- `auxiliary`：允许的辅助核算维度（`department` / `customer` / `supplier` / `employee` / `project`）
- `defaultChild`：**给上级科目增设明细后不必改规则**。例如 `1002 银行存款` 配了 `defaultChild: "1002.01"`，
  规则里写 `1002` 时会自动下钻到 `1002.01 基本户`。

### 记账规则 `config/mappings/*.yaml`

```yaml
- id: bank-fee
  desc: 银行手续费
  kinds: [bank]           # 适用单据类型
  priority: 780           # 越大越先匹配，命中第一条即停止
  when:
    summary: [手续费, 服务费, 工本费]   # 摘要包含任一关键字
    direction: out                     # 资金方向
    amountMax: 1000                    # 金额上限（元）
  then:
    entries:
      - { side: debit,  account: "6603.02", amount: total, summary: "银行手续费：{summary}" }
      - { side: credit, account: "1002",    amount: total }
  warn: "如需按银行分设明细科目，请修改本规则"
```

**条件（when）**——声明的多个条件之间是「与」关系：

| 字段 | 说明 |
| --- | --- |
| `summary` | 摘要包含任一关键字 |
| `summaryAll` | 摘要必须包含全部关键字 |
| `summaryRegex` | 摘要匹配正则 |
| `summaryNot` | 摘要不得包含任一关键字 |
| `direction` | `in` 收 / `out` 付 / `none` |
| `counterparty` | 往来单位包含任一关键字 |
| `amountMin` / `amountMax` | 金额区间（单位：**元**） |
| `dateFrom` / `dateTo` | 日期区间（`YYYY-MM-DD`，含端点） |
| `fields` | 专有字段精确匹配，如 `{ stage: payment }` |
| `fieldContains` | 专有字段包含关键字，如 `{ category: [差旅费] }` |
| `anyOf` / `allOf` / `not` | 子条件组合 |

> 条件里写错字段名会直接报错，而不是被静默忽略——拼错的字段会让条件变成「恒真」，
> 那会让一条精确规则去匹配所有单据，这类 bug 极难排查。

**分录金额来源（amount）**：

| 取值 | 含义 |
| --- | --- |
| `total` | 单据总金额（默认） |
| `net` | 不含税金额 |
| `tax` | 税额 |
| `balanced` | 差额配平，自动补足借贷差额 |
| `field.xxx` | 取单据专有字段的金额，如 `field.netPay` |

**占位符**：`{summary}` `{counterparty}` `{date}` `{amount}` `{field.xxx}` 可用于 `account`、`summary`、`auxiliary`。

**金额为 0 的分录会自动删除**（由 `settings.yaml` 的 `dropZeroLines` 控制）。
正因如此，一条规则可以同时适配「有进项税」和「无进项税」两种情况：

```yaml
then:
  entries:
    - { side: debit,  account: "6602.04",    amount: net }      # 无票时 net = 全额
    - { side: debit,  account: "2221.01.01", amount: tax }      # 无票时 tax = 0 → 自动删除
    - { side: credit, account: "1002",       amount: total }
```

### 全局设置 `settings.yaml`

| 设置 | 说明 |
| --- | --- |
| `companyNames` | **必填**。本企业工商全称（可多个），用于判断发票进项/销项、合同甲乙方 |
| `expenseCreditAccount` | 报销单贷方科目。`2241.04` 先挂账（**同时处理银行流水时用这个**）；`1002` 视为直接付款 |
| `suspenseAccount` | 兜底科目，默认 `1901` 待处理财产损溢 |
| `voucherWord` | 凭证字，默认「记」 |
| `mergeByDate` | 是否把同一天的凭证合并为一张 |
| `dropZeroLines` | 是否删除金额为 0 的分录行 |
| `departments` | 已知部门列表，用于辅助核算识别 |
| `defaultTaxRate` | 未识别到税率时使用的默认税率 |

### 去重规则 `dedup.yaml`

```yaml
- id: payroll-payment-duplicate
  desc: 银行代发的工资与工资表生成的发放凭证是同一笔业务
  keep: { kinds: [payroll], fields: { stage: payment }, amountField: netPay }
  drop: { kinds: [bank], summary: [代发工资, 工资代发] }
  windowDays: 10
  amountTolerance: 0.01
```

去重策略刻意保守：**金额必须一致 + 日期必须在窗口内**才判定为同一笔业务。
宁可漏判（留告警给人看），也不误判（悄悄吃掉一笔真实业务）。

## 会计处理规则详解

### 银行流水

| 摘要关键字 | 借方 | 贷方 |
| --- | --- | --- |
| 收到货款、销售款、回款 | 银行存款 | 应收账款（挂客户） |
| 支付货款、采购款、材料款 | 应付账款（挂供应商） | 银行存款 |
| 手续费、账户管理费、跨行费 | 财务费用-手续费 | 银行存款 |
| 结息、利息（收） | 银行存款 | 财务费用-利息收入 |
| 贷款利息（付） | 财务费用-利息支出 | 银行存款 |
| 代发工资 | 应付职工薪酬-工资 | 银行存款 |
| 缴纳社保 / 公积金 | 应付职工薪酬-社保 / 公积金 | 银行存款 |
| 缴纳增值税 / 个税 / 所得税 / 附加税 | 应交税费-对应明细 | 银行存款 |
| 提现 / 存现 | 库存现金 ↔ 银行存款 | |
| 理财申购 / 赎回 | 交易性金融资产 ↔ 银行存款 | |
| 定期存款转存 | 其他货币资金-定期存款 | 银行存款 |
| 收到 / 支付预收款、定金、保证金 | 银行存款 ↔ 预收账款 / 预付账款 | |
| 报销款 | 其他应付款-员工报销款 | 银行存款 |
| 电费、水费、物业费 | 管理费用-水电费 | 银行存款 |
| 房租、场地租金 | 管理费用-租赁费 | 银行存款 |
| 其它未识别 | 应付账款 / 应收账款（+ 告警） | 银行存款 |

### 发票

**进项（我们采购）**

- 可抵扣（专用发票）：`借 存货/固定资产/费用（不含税）` + `借 应交税费-应交增值税(进项税额)`，`贷 应付账款（价税合计）`
- 不可抵扣（普通发票、免税）：`借 存货/固定资产/费用（价税合计全额）`，`贷 应付账款`

**销项（我们销售）**

- `借 应收账款（价税合计）`，`贷 主营业务收入（不含税）` + `贷 应交税费-应交增值税(销项税额)`

### 工资（三段式）

```
计提：借 管理费用/销售费用/制造费用-工资        贷 应付职工薪酬-工资
发放：借 应付职工薪酬-工资                     贷 银行存款（实发）
                                                   应交税费-应交个人所得税
                                                   其他应付款-社保个人部分
                                                   其他应付款-住房公积金个人部分
单位：借 管理费用/销售费用/制造费用-社保公积金   贷 应付职工薪酬-社会保险费 / 住房公积金
```

部门决定费用归属：销售部/市场部 → `6601 销售费用`；生产部/车间/品质部/物流部 → `5101 制造费用`；其余 → `6602 管理费用`。

### 报销

```
报销单：  借 费用明细科目（按类别+部门）  + 借 进项税额（如有专票）  贷 其他应付款-员工报销款
银行付款：借 其他应付款-员工报销款                                    贷 银行存款
```

两张凭证合起来才是完整业务。**如果你只处理报销单、不导入银行流水**，
请把 `expenseCreditAccount` 改成 `"1002"`。

## 输出的 Excel 长什么样

导出的工作簿包含 6 张表：

| 工作表 | 内容 |
| --- | --- |
| **记账凭证** | 分录明细，含凭证字号、日期、摘要、科目、借贷金额、辅助核算、来源文件/工作表/行号、命中规则；每张凭证后有小计行和平衡状态 |
| **科目汇总表** | 按科目汇总借贷发生额与余额方向，底部给出试算平衡结果 |
| **单据台账** | 识别出的每一条原始单据，含关键字段与来源定位；合同台账也在这里 |
| **问题与待办** | 按错误/警告/提示分级的全部问题，带来源文件与行号 |

| **处理说明** | 本次运行的参数、统计、配置指纹与文件清单 |

金额一律写成**数值**（两位小数格式），不用文本，便于财务软件直接导入。

## 已知限制与人工复核点

这个工具的目标是**把 80% 的机械劳动自动化，并把剩下 20% 需要判断的地方清楚地标出来**，
而不是假装能 100% 全自动。以下是刻意保留人工介入的地方：

1. **期初余额不在范围内。** 银行对账单的期初余额不生成凭证，需在金蝶/用友中录入，
   否则银行存款科目余额会整体偏移。

2. **缴纳社保/公积金需要人工拆分。** 银行流水只有一笔总额，无法区分单位部分与个人部分。
   系统会记入 `应付职工薪酬-社保` 并告警。正确做法是拆成
   `借 应付职工薪酬-社保（单位）+ 借 其他应付款-社保个人（个人）`。

3. **销项发票默认挂应收账款。** 若已收款请改为银行存款，或核对银行流水中的对应收款。

4. **合同不含存货/费用科目信息。** 合同付款分录会暂挂 `1901`，需按发票内容调整到正确科目。

5. **去重是保守的。** 金额或日期对不上就不会去重，会留告警给你判断。

6. **兜底规则会兜住一切。** 未识别的业务会按「收回应收账款 / 支付应付账款」处理并告警，
   请务必逐条复核「问题与待办」里的警告。

7. **老式 `.xls` 需先转换**（见上文 `convert-xls.ps1`）。`.doc` 需先另存为 `.docx`。

8. **生成的凭证是草稿。** 请人工复核后再导入财务软件。
   特别提醒：走「待处理财产损溢 1901」和「【系统配平】」的分录必须清理。

### 代码结构

```
src/
├── core/           核心：类型契约、金额、日期、文本、规则引擎、配置、去重
│   ├── types.ts        全局类型契约（数据流：文件 → 单据 → 凭证）
│   ├── money.ts        金额运算（分为单位的整数，禁止浮点）
│   ├── datetime.ts     日期解析（Excel 序列号、中文日期…）
│   ├── text.ts         中文文本规范化与模糊匹配
│   ├── rules.ts        规则引擎：条件求值、金额分配与配平
│   ├── config.ts       YAML 配置加载与校验
│   └── dedup.ts        跨单据重复业务检测
├── io/             读取层：Excel/CSV、Word、表头语义映射
├── extract/        提取器：五类单据 → 统一的 DocumentRecord
├── ledger/         记账层：凭证生成、借贷平衡校验、试算平衡
├── export/         导出层：Excel 凭证工作簿
├── pipeline.ts     端到端编排
├── cli.ts          命令行入口
└── web/            Web 界面（原生 http，无框架）
```

### 设计原则

1. **金额绝不用浮点。** 全程以「分」为单位的整数运算。
2. **不确定就不猜。** 日期解析失败返回 `null` 并告警，而不是猜一个日期；宁可让人看一眼。
3. **不平就报错。** 凭证借贷不平会挂到待处理科目并报错级问题，绝不悄悄吞掉差额。
4. **一切可溯源。** 每条分录都带「文件 / 工作表 / 行号 / 命中规则」。
5. **配置优于代码。** 会计科目和业务规则都是 YAML，财务人员可以自己改。
6. **失败要可解释。** `explain` 命令能展示每个字段的识别依据与规则的匹配明细。

### 测试

90 项测试覆盖金额与日期解析、文本匹配、规则引擎、配置校验、跨单据去重，
以及从文件到凭证的端到端链路（含银行流水表头探测、发票价税分离、工资勾稽、合同要素抽取、自动配平）。

测试曾经抓到过的真实 bug（都由回归测试锁住）：

- 中文大写金额漏「零」：`904000` 应写「玖拾万**零**肆仟元整」而非「玖拾万肆仟元整」（央行票据填写规定）
- 合同税率正则回溯：把「增值税税率 13%」误读成「3%」
- `allocate` 返回 `-0`，导出时会显示成 `-0.00`
- 日期解析会「猜」非法月份：`2024-13-01` 被拼成 `2024-01-13`
